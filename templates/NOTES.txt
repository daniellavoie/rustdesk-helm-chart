1. Get the public key. Clients need it, and you should back it up — losing it disconnects
   every enrolled client permanently:

     kubectl get secret -n {{ .Release.Namespace }} {{ include "rustdesk-server.keySecretName" . }} \
       -o jsonpath='{.data.{{ .Values.key.publicKeyKey | replace "." "\\." }}}' | base64 -d; echo

   The Secret is the source of truth; the volume is only a cache of it. It is not owned by
   Helm, so it deliberately survives `helm uninstall` and a later reinstall will reuse it.

     ID Server:    {{ include "rustdesk-server.tailscale.fqdn" (dict "ctx" . "role" "hbbs") }}
     Key:          <the public key from step 1>

   Clients on the tailnet use the hbbs address as their ID server. hbbs and hbbr are two

   If that address is private and clients reach you through NAT, use your PUBLIC hostname or
   IP below instead, and forward these ports to the Service addresses:

     {{ include "rustdesk-server.hbbs.natTestPort" . }}/tcp, {{ .Values.hbbs.port }}/tcp and {{ .Values.hbbs.port }}/udp  -> hbbs
     {{- if .Values.hbbr.enabled }}
     {{ .Values.hbbr.port }}/tcp                             -> hbbr
     {{- end }}
{{- else if eq .Values.hbbs.service.type "NodePort" }}

     kubectl get svc -n {{ .Release.Namespace }} {{ include "rustdesk-server.roleFullname" (dict "ctx" . "role" "hbbs") }} \
       -o jsonpath='{range .spec.ports[*]}{.name}{"\t"}{.port}/{.protocol}{"\t-> node:"}{.nodePort}{"\n"}{end}'

   Point your port forwarder at those node ports, from the PUBLIC ports clients expect:

     {{ include "rustdesk-server.hbbs.natTestPort" . }}/tcp, {{ .Values.hbbs.port }}/tcp and {{ .Values.hbbs.port }}/udp  -> hbbs node ports

     {{- end }}

   Note that {{ .Values.hbbs.port }} needs BOTH a TCP and a UDP forward. They are separate rules on
   most forwarders, and each protocol gets its own node port.

   Service type is {{ .Values.hbbs.service.type }}. Clients must reach {{ .Values.hbbs.port }}/tcp AND {{ .Values.hbbs.port }}/udp.

{{- if and (eq .Values.hbbs.service.type "LoadBalancer") (ne .Values.hbbs.service.externalTrafficPolicy "Local") }}

WARNING: hbbs.service.externalTrafficPolicy is "{{ .Values.hbbs.service.externalTrafficPolicy }}", not "Local". The source address
of every client will be rewritten, so hbbs will hand peers the wrong endpoint for hole
punching. Sessions will still connect — through the relay, every time — which makes this
look like a working install while consuming relay bandwidth for traffic that should be
peer to peer.
{{- end }}
{{- range $role := (list "hbbs" "hbbr") }}
{{- $cfg := index $.Values $role }}
{{- if and $cfg.enabled (eq $cfg.service.type "NodePort") (eq $cfg.service.externalTrafficPolicy "Local") (not $cfg.nodeSelector) (not $cfg.affinity) }}

WARNING: {{ $role }} uses NodePort with externalTrafficPolicy "Local" and is not pinned to a node.
"Local" means ONLY the node currently running the {{ $role }} pod answers on its node port; every
other node drops the traffic silently. If your port forwarder targets a fixed node -- and most
do, since they cannot see Endpoints -- it will point at a black hole whenever the pod is
scheduled elsewhere, and nothing will report an error.

Either pin the pod with {{ $role }}.nodeSelector or {{ $role }}.affinity and target that same node,
or point the forwarder at an address that follows the pod. Do NOT "fix" this by switching to
externalTrafficPolicy "Cluster": that rewrites the client source address, and every session
will silently fall back through the relay.
{{- end }}
{{- end }}
